Strengthen durable graph construction through the existing `build_or_update_graph` function and `GraphStore` class. Do not add a new public class to `code_review_graph.graph`, or change the function’s parameters, established result fields and summaries, existing warning meanings, or exception behavior. New narrow warnings for recovery and construction-context incompatibility are required below.

A build must capture one repository inventory and one complete construction context before preparing output. That context must account for every input capable of changing requested results, including source bytes, repository identity, discovery and ignore settings, submodule selection, custom languages, runtime, schema, parser and resolver implementations, requested post-processing, and explicitly requested embedding configuration. Reuse is valid only when the complete context and independently verified published content remain compatible. Repository tests are regression checks; additional behavioral checks may enforce this complete contract.

Read each source into an immutable byte snapshot and use those same bytes for language detection, hashing, parsing, and relationship extraction. Incremental updates must reconstruct changed files and the complete transitive reverse-dependent closure, reparsing each affected file once. If expansion reaches any bound before a fixed point, transparently perform a full reconstruction. Reconcile the captured inventory so deleted, renamed, moved, ignored, unsupported, or submodule-removed files leave no observable stale nodes, edges, search results, embeddings, flows, communities, summaries, or risk results.

Use `GraphStore` as the sole publication authority. Base relationships, resolver output, requested derived output, internal context evidence, and an independently recomputed content-integrity digest must take effect in one atomic publication transition. Readers must observe either the complete previous publication or the complete next one. Concurrent builds with different inventories or settings must hold exclusive access for the duration of candidate preparation and publication; they must not interleave candidate work. Do not mark a candidate reusable before all requested work and validation succeeds.

Missing durable state is an ordinary first build and must not emit a recovery warning. Unreadable, malformed, truncated, integrity-invalid, schema-incompatible, or context-incompatible state must produce a narrow warning through the existing logging and result-warning channels and trigger clean reconstruction. Validate graph content by recomputing its digest rather than trusting the stored context fingerprint alone. Migration, parsing, resolution, post-processing, integrity preparation, or publication failure must leave the previous complete publication usable. Preserve and re-raise the original `KeyboardInterrupt` object unchanged.

Resolver and optional-stage failures may retain established warning isolation, but stale output from a failed stage must not appear current: withhold the candidate and retain the prior complete publication. Omitting embedding provider and model must not refresh embeddings. `full_rebuild` must reject reusable graph content while producing results semantically equivalent to a successful clean build.

Preserve repository-root and data-location precedence, schema migration support, stored-path compatibility, multi-language and custom-language behavior, ignore rules, submodules, source-control fallbacks, impact direction, search, review, flow, community, statistics, and visualization semantics. Keep synchronization, context fingerprints, integrity digests, storage layout, and private implementation types internal.
